# 全屏 AOD 闪烁根治方案（研究版 2026-11-22）

## 一、机理定论（学术文献，四篇 SID/期刊互证）

闪烁根源 = **低频驱动下 TFT 存储电容保持期的亮度漂移**，不是 PWM 本身：
- LTPS 面板：T3/T4 为 LTPS TFT，存储电容 Cst 漏电 + 驱动管 D-TFT 迟滞/电子俘获 → **每帧保持期内亮度逐渐爬升**，低频（AOD 常 1-30Hz skip-frame 驱动）时该爬升以驱动频率重复 → 肉眼可见闪烁（SID P-4: LTPS 1Hz AOD 低亮度闪烁严重；IEEE 3197171: 灰阶 15 时漂移 5.7%/灰阶 255 时 1.9%）。
- 帧内 ~60Hz 的 PWM 调光脉动**不是**闪烁源（频率高看不见）；**慢速亮度爬升才是**。
- 与观察完美吻合：①AOD 低频驱动 → 任意亮度都闪；②正常态 60-120Hz 每帧重编程 → 极低亮度也不闪；③AOD 下 vsync 极低、监测工具冻结失效（Nothing 社区同款报告："hz indicator turns off on aod"）。

## 二、设备事实：Nothing Phone 3 = LTPS AMOLED（非 LTPO！）

- 6.67" 1.5K LTPS AMOLED，**30-120Hz** 自适应（30/60/90/120 四档），2160Hz PWM 低亮度调光。
- LTPS 特性决定低频段闪烁更敏感（LTPO 用 IGZO 管保 Cst，LTPS 漏电大——正是文献里"1Hz AOD 闪烁重灾"的同一问题）。
- AOD 时系统刻意压到最低刷新率省电（AOSP SurfaceFlinger 补丁明文："SF: Use lowest possible refresh rate in doze mode"）→ 30Hz 或更低的 skip-frame 驱动 → 闪烁。

## 三、根治方案（三档递进）

### 档 A｜无侵入（先试，5 分钟）
```
settings put system min_refresh_rate 60   # 或 120
settings put system peak_refresh_rate 120
```
锁屏进 AOD 看闪不闪。可能被 doze 策略忽略（AOSP 补丁明示 doze 不遵守用户限制），但 NothingOS 未必同款，值得一试。

### 档 B｜SurfaceFlinger 属性（root，机制白送）
AOSP Scheduler 显示电源逻辑原文：**"If Display Power is not in normal operation we want to be in performance mode"**——只要给 display-power 定时器，非 normal 电源态（即 doze/AOD）保持 PERFORMANCE 刷新率：
```
resetprop ro.surface_flinger.set_display_power_timer_ms 60000
killall surfaceflinger   # 重启 SF
```
（2019 引入的机制，Android 17 需验证仍在；若在，这是官方留的口子。）

### 档 C｜Xposed 根治（用户方案，最彻底）
**让 AOD 态的屏幕电源状态 = 平时（POWER_MODE_NORMAL），仅亮度降低。**
- 钩子点（Java 层）：`com.android.server.display.DisplayPowerController` / `DisplayManagerService` 的 doze 电源态决策——阻止切到 DOZE/DOZE_SUSPEND，改用 NORMAL + doze 亮度。
- 效果：面板保持 60-120Hz 正常驱动 → 与"正常态低亮度不闪"完全同机理 ✓ 根治。
- 代价：失去 doze-suspend 省电（功耗升）——与我们已有的「定时转普通 AOD」功能天然互补（夜里定时切走控功耗）。
- 风险：UDFPS/指纹唤醒、烧屏（LTPS 低亮常显）、AOD 渲染管线兼容。
